# 技术与产品决策记录

记录影响长期实现方式的决策，不记录普通执行日志。

### 开源仓库名用 Figma-MCP，MIT，不上传本地复刻产物

- 日期：2026-09-12
- 状态：已确认
- 背景：用户要求把本 MCP 开源到 GitHub，并指定仓库名为 `Figma-MCP`。
- 选择：公开仓库 `huaer9000/Figma-MCP`，MIT 许可。对外名称用 Figma-MCP；本机目录、Figma 插件显示名仍为「Figma设计桥接」；MCP 服务名仍为 `figma-bridge`。`repro/` 不进仓库。
- 原因：`repro/` 是本机复刻对照图和站点资源，体积大，也不是 MCP 运行所必需。改插件显示名或服务名会打断已经在用的本机配置。
- 影响：克隆后的目录名是 `Figma-MCP`。安装说明以 README 为准。
- 替代方案：连同 `repro/` 一起公开；或把插件也改名为 Figma-MCP。

### 自建插件桥，不用官方 MCP，也不先用开源成品

- 日期：2026-09-10
- 状态：已确认
- 背景：官方 Figma MCP 需要会员。用户要免费操作当前打开文件：读取、切图、写入，并做像素级还原。
- 选择：自己做 Figma 桌面端插件 + 本机 MCP。
- 原因：官方通道付费；REST 不能绑定当前画布且写入弱；开源成品能验证通路，但协议与像素级合同不可控。
- 影响：必须维护插件与本地服务；插件关闭即不可用。
- 替代方案：官方 MCP；`cursor-talk-to-figma-mcp` 等开源桥。

### MCP 与 WebSocket 同一进程

- 日期：2026-09-10
- 状态：已确认
- 背景：社区方案常要先起 socket 再起 MCP，容易漏步骤。
- 选择：一个 Node 进程同时提供 stdio MCP 和 `127.0.0.1` WebSocket。
- 原因：任意 MCP 客户端拉起本服务即拉起桥；插件只连默认端口。
- 影响：MCP 退出桥也退出；端口与 MCP 生命周期绑定。Cursor 等客户端重启 MCP 时会先停旧进程再拉新进程，必须立刻放端口，并允许约 2 秒的绑定重试，否则新进程会因撞上自己而失败，插件变未连接。
- 替代方案：独立 socket 进程。

### 对 Agent 只暴露标准 MCP，不绑定 Cursor

- 日期：2026-09-10
- 状态：已确认
- 背景：用户明确要求除 Cursor 外，其他 Agent 也能用。
- 选择：对外只做标准 MCP stdio；工具名、协议、插件都不依赖某一家客户端。配置用「命令 + 参数」。
- 原因：Cursor、Claude Code、Codex、OpenCode 等都能拉起 stdio MCP。绑定 Cursor 会把产品锁死。
- 影响：第一版不提供本机 HTTP MCP；两个客户端同时各起一份服务会抢 `17653`，第二份必须失败。换 Agent 用可以，双开不行。
- 替代方案：独立常驻桥 + 多个薄 MCP 适配；或第一版就做 Streamable HTTP。

### 像素级主路径是落盘，不是对话内 JSON/图片

- 日期：2026-09-10
- 状态：已确认
- 背景：即时设计 MCP 已用 `outputPath` 避开 MCP 传 base64 被截断。大框 REST JSON 也会撑爆上下文。
- 选择：`figma_export_node` 与 `figma_read_for_implement` 必写本地文件；MCP 只回路径和元数据。
- 原因：像素级核对必须看到完整图；结构以文件为准可反复读。
- 影响：Agent 必须会读本地文件；调用时要带绝对路径。
- 替代方案：MCP 内嵌 base64 或截断树。

### layout 合同自算 boundsInRoot，REST JSON 为可选加深

- 日期：2026-09-10
- 状态：已确认
- 背景：Plugin API 的 `JSON_REST_V1` 字段全，但不是所有 Figma 版本都有，且体积大。
- 选择：日常用自研 `layout`；`rest_json` / `rest.json` 能导出就导出，不能则明确失败或缺省，不冒充。
- 原因：`layout` 可控、带 `boundsInRoot`，适合写代码；REST 作补全。
- 影响：要自己维护序列化；与官方 REST 字段不完全同名。
- 替代方案：只导出 REST JSON。

### 第一版单会话、无鉴权、只绑 loopback

- 日期：2026-09-10
- 状态：已确认
- 背景：本机工具，降低第一版复杂度。
- 选择：只接受一个插件连接；监听 `127.0.0.1`；暂不设令牌。
- 原因：先打通闭环。同机其它进程理论上能操作当前文件，作为已知风险接受。
- 影响：多文件同时桥接不可用；共享电脑有风险。
- 替代方案：频道号、共享令牌。

### 工具集薄而全，不对齐即时设计全量 API

- 日期：2026-09-10
- 状态：已确认
- 背景：用户要读、写、切图都齐，但项目按 MVP 验证效果。
- 选择：以 21 个 `figma_*` 工具覆盖三类能力，并在复刻带摄影的落地页时补上第 22 个 `figma_create_image`（只读本机文件）；组件/变体/变量留到以后。
- 原因：三类能力都能验收，又不把第一版做成大而全的设计 API。
- 影响：复杂稿（组件库、变体）第一版只能当普通树来读。
- 替代方案：第一版只做读取；或一次做齐即时设计同款工具。

### 复刻画板优先嵌套 Auto Layout

- 日期：2026-09-10
- 状态：已确认（用户：设计尽量做成 Auto Layout，方便以后改）
- 背景：手摆坐标的落地页改一行字就要重算整页。
- 选择：区块用垂直/水平 Auto Layout；按钮用 Frame 包文案并十字居中。只有压图、印章重叠才用 `layoutPositioning: ABSOLUTE`。桥补上 `horizontalSizing` / `verticalSizing` / `layoutPositioning`，以及 `set_fill.clear` 去底。
- 原因：用户改文案或增减条目时，间距和居中应跟着走。
- 影响：没设 FIXED/FILL 的横排区块会 HUG 变窄。
- 替代方案：整页继续绝对定位。

### 写入原则通过 MCP instructions 与 Resource 下发

- 日期：2026-09-10
- 状态：已确认（用户：设计原则写进 MCP，让别人的 Agent 实现时避开同类问题）
- 背景：别的 Agent 只看得到 MCP 表面，读不到本仓库 `AGENTS.md` / `CONTEXT.md`。复刻落地页时反复踩到图文乱叠、手摆按钮、HUG 变窄、色块冒充插图。
- 选择：握手带短 `instructions`；完整条文挂资源 `figma://write-guidelines`；相关写入工具描述补一句提醒。正文集中在 `shared/write-guidelines.ts`。
- 原因：`instructions` 最容易被客户端自动注入；Resource 可展开；工具描述在动手时提醒。单独做「请先读原则」工具不可靠。
- 影响：改原则要改共享正文并重启 MCP。Aetherfield 等单页量测继续留在 `CONTEXT.md`，不进全局说明。
- 替代方案：只加长工具描述；或只做 Resource 指望 Agent 主动读取。

### 复刻先做图层盘点，不能只抄文案和照片

- 日期：2026-09-10
- 状态：已确认（用户：复刻不够好，要避开漏渐变、分割线、编号、图标，并尽量 100% 还原）
- 背景：Agent 按「标题 + 正文 + 摄影 + 按钮」写完就停。头部渐变被铺成纯色，列表缺编号和分割线，卡片缺图标。`figma_set_fill` 也写不了渐变和混合。
- 选择：跨稿原则增加图层盘点（底 / 容器底 / 描边 / 列表铬 / 饰件 / 字 / 图 / 按钮 / 效果）。动手前先列出所有非透明背景和 `border>0`。纯色不能代替渐变或 multiply；这类层先落成本机 SVG/PNG 再 `figma_create_image`。按块导出对照，缺一层不算完。
- 原因：漏的不是「某一页的坐标」，而是一类稳定的层。不写进 MCP，下一个 Agent 还会只抄内容。
- 影响：改原则后必须重启 MCP。第一版仍无原生渐变 / blendMode 工具。
- 替代方案：立刻扩 MCP 写渐变和混合；或做自动截图对比。两者都更重，先用盘点 + 落盘绕过。
- 2026-09-10 补强：用户指出案例卡灰底和首屏图黑描边仍被漏。盘点把「底」只理解成全宽洗、把「图」理解成已贴照片，就会漏容器填充和 border。原则拆出容器底和描边，并要求先做铬清单。

### 插件主线程到 UI 的大图必须传独立 TypedArray

- 日期：2026-09-11
- 状态：已确认
- 背景：整页 PNG（约 1920×5978）导出成功后，插件主线程被 Figma 杀掉，面板自己关掉，随后 MCP 报 `PLUGIN_NOT_CONNECTED`。用户并未关插件。
- 选择：分片继续按 256 KiB；主线程 `postMessage` 只传独立 `Uint8Array`，片间 `setTimeout(0)` 让出；UI 再转 base64 上 WebSocket。
- 原因：`Array.from(256KiB)` 会做出数十万个 Number，再同步狂发，会打满沙箱堆或触发看门狗。`chunkBytes` 的 subarray 若直接 postMessage，structured clone 还可能带上整图 backing store。
- 影响：大图导出必须走 `plugin/src/bin-transfer.ts`。改发送路径后要重新运行插件，不必为这一项单独重启 MCP。
- 替代方案：主线程直接编 base64 字符串；或把插件侧分片再缩小。TypedArray + 让出更省 CPU，也不改 WS 协议。

### 心跳只 ping 保活，不因漏 pong 断开

- 日期：2026-09-11
- 状态：已确认
- 背景：整页导出后插件仍活着。中间几分钟只在浏览器量官网、没有插件调用。下一次写入报 `PLUGIN_NOT_CONNECTED`。用户没有关插件，也不是大图发送把主线程打挂。
- 选择：默认 `closeAfterMissedPongs = 0`。仍每 20s 发协议层 `ping`，但不把漏 `pong` 当成死连接。测试或将来有可靠 pong 的客户端时，可显式传入大于 0 的次数。
- 原因：Figma 插件 iframe 常常不回 WebSocket `pong`。旧逻辑先把 `missedPongs += 1`，漏 2 次（约 60s）就 `socket.close()`。UI 的 3s 重连在 iframe 被节流时也可能起不来，于是一直显示未连接。
- 影响：改桥后必须 `npm run build` 并重启 Cursor 的 `figma-bridge`（可改 `FIGMA_BRIDGE_BOOT`）。不要再起 `npm run bridge`。
- 替代方案：改成应用层 JSON ping，由插件 UI 必回应；或探测 iframe 可见性再决定是否掐断。默认不因漏 pong 断开更小，也不改插件协议。

### 第一版补上可写效果，毛玻璃走 BACKGROUND_BLUR

- 日期：2026-09-11
- 状态：已确认
- 背景：苹果导航是 `rgba(250,250,252,0.8)` + `blur(20px)`。22 个工具写不了效果，只能铺实底，被当成没做。
- 选择：增加第 23 个工具 `figma_set_effects`。第一版只写 `BACKGROUND_BLUR` / `LAYER_BLUR` / `DROP_SHADOW` / `INNER_SHADOW`。`figma_set_text_style` 同时允许改 `characters`，否则断行只能删了重建。
- 原因：半透明实色不能代替背景模糊；标题和链接若在同一个文本节点里，也无法分开填色。
- 影响：必须构建、重启 MCP，并重新运行插件。官网首屏导航底下是白底，静帧上磨砂几乎等于实底；要在导出图里看见磨砂，导航必须压到后面的图上。
- 替代方案：用一张磨砂 PNG 冒充。那不是效果，滚动或换底会立刻穿帮。

### 字压图、铺满背景、构图和完整目录写进跨稿原则

- 日期：2026-09-11
- 状态：已确认
- 背景：苹果官网复刻里，Watch 12 把 914×638 产品图拉成 900×900 导致文案压住表盘；AirPods 用窄图两侧露黑；Ultra 用了侧面剪影而不是 3/4 俯视首帧；页脚用简化五列冒充完整目录。
- 选择：写入原则增加到 16 条。字压图必须落在留白；背景摄影 `scaleMode: FILL` 并与区块同尺寸；底要核对照片构图；页脚/导航目录必须列齐全。
- 原因：漏的不是某一页坐标，而是会反复出现的写法。不写进 MCP，下一个 Agent 还会先铺字再补层。
- 影响：改原则后必须构建并重启 `figma-bridge`。单页量测仍不进全局说明。
- 替代方案：只记在本仓库文档里。别的 Agent 看不到 `docs/`，还会再犯。
