# 产品文档

开源仓库名是 **Figma-MCP**。Figma 插件显示名仍为「Figma设计桥接」。Agent 侧服务名建议继续用 `figma-bridge`。

## 用户与问题

用户是用各种 Agent 写界面的人（Cursor、Claude Code、Codex、OpenCode 等）。手头有 Figma 桌面端里打开的设计稿，但没有 Figma 官方 MCP 会员，不能用官方通道读文件、切图、改画布。

本项目对 Agent 的接口是标准 MCP，不绑定某一家客户端。没有这条桥，Agent 只能看截图或口头描述，做不到对着当前文件做像素级还原，也不能在 Figma 里直接改稿。

## 目标与成功标准

让 Agent 通过本项目的本地插件，操作**当前打开的 Figma 文件**：读取、切图、写入三类能力同时可用。成功标准见 `docs/TECH.md` 第 1.2 节。

像素级还原的含义：Agent 拿到的不是「大概长什么样」，而是根节点相对坐标、颜色、字号、间距，外加一张可打开的预览图，能按数值写代码并用预览图对照。

## 当前范围

第一版同时包含：

- 读：当前文件、当前页、选区、节点树、像素级打包读取
- 切图：按节点导出 PNG / JPG / SVG / PDF 到本地路径
- 写：创建 Frame / 矩形 / 椭圆 / 文本 / 本地图片，改位置尺寸填充描边圆角文本、效果（背景模糊 / 阴影）和 Auto Layout（含 FILL / HUG / 绝对定位），移动与删除

插件只做连接状态，不做设计编辑器。

## 非目标

- 替代官方付费 MCP 的云端能力（Variables 深度、Code Connect、跨文件）
- 绑定某一家 Agent 客户端
- 第一版让两个 Agent 同时连同一座桥
- 网页版 Figma
- 第一版做齐组件、变体、样式库、原型
- 把本项目做成即时设计 MCP 的完整复刻

## 审美与偏好

- 插件面板只显示连接与错误，不做装饰性界面。
- 给 Agent 的错误信息用中文，带节点 id 或路径。
- 切图和像素级读取以本地文件为准，不在对话里塞大段 base64。
- 写入画布的跨稿原则通过 MCP `instructions` 和资源 `figma://write-guidelines` 下发，不依赖本仓库文档。不把某一页的量测写进全局说明。
- 复刻必须先做图层盘点：底、容器底、描边、列表铬、饰件、字、图、按钮、效果。只摆文案和照片不算还原完。有图不等于没有描边；白底页面不等于卡片没有灰底。
- 字压图时，文案必须落在图的留白里，不能压住产品主体。背景摄影要铺满容器（`scaleMode: FILL`）。底要核对照片是哪一张、什么构图。页脚和导航目录必须按官网列齐全。

## 核心流程

1. 打开 Figma Desktop 中的目标文件。
2. 运行本项目的开发版插件，看到「已连接」。
3. 在任意已配置本 MCP 的 Agent 里说话。握手时客户端会收到写入原则（`instructions`）；完整条文在资源 `figma://write-guidelines`。Agent 先查 `figma_status`。
4. 用户选中要还原的 Frame。Agent 调用 `figma_read_for_implement`，到本地目录取 `preview.png` 和 `node.json`。
5. Agent 按 `boundsInRoot` 与 Auto Layout 写代码，用预览图核对。
6. 若要改稿，Agent 调用写入工具，再读回或再导出对照。

同一套插件和同一套工具，不随客户端更换。第一版同一时间只应有一个 MCP 进程占用桥；换一个 Agent 用可以，两个一起抢端口不行。

## 验收标准

- 未开插件时，工具立即报未连接，不空等超时。
- 开着插件时，能对当前选区完成一次「读结构 + 出预览图 + 切一张 SVG + 画一个矩形」的闭环。
- 预览图与画布观感一致；返回的宽高与 Figma 中该 Frame 一致。
- 不要求第一版就能还原带复杂组件库的整页设计系统。
